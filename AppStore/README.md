# App Store metadata

The App Store Connect texts, kept in the project. Nothing is uploaded
automatically — open the file, copy the contents, paste it into the matching
field in App Store Connect.

The folders are named after the fastlane convention (`cs`, `en-US`), so if you
ever decide to move to `fastlane deliver`, renaming `AppStore/` to
`fastlane/metadata/` is all it takes. The layout is the Sudoku project's
(github.com/RobertLib/sudoku), so the two listings are maintained the same way.

## Where everything goes

App Store Connect → **Apps → Wordwander → iOS App → 1.0 Prepare for Submission**
(the version in `MARKETING_VERSION` — keep the two in step). There is a language
switch at the top — every field is filled in separately for each language.

| Field in App Store Connect | File | Limit | Currently |
|---|---|---|---|
| App Name | `<language>/name.txt` | 30 characters | 26 / 29 |
| Subtitle | `<language>/subtitle.txt` | 30 characters | 30 / 30 |
| Promotional Text | `<language>/promotional_text.txt` | 170 characters | 146 / 150 |
| Description | `<language>/description.txt` | 4000 characters | 2515 / 2342 |
| Keywords | `<language>/keywords.txt` | 100 **bytes** (UTF-8) | 95 / 98 |
| What's New in This Version | — | 4000 characters | not on a first version |
| App Review Information › Notes | `review-notes.txt` (English only) | 4000 characters | 3940 |
| App Preview and Screenshots | generated by the scripts, see [screenshots.md](screenshots.md) | 1–10 images, up to 3 previews | 10 + video |

(The two numbers are `cs` / `en-US`, in that order.)

The keyword field is the one limit Apple counts in bytes rather than characters,
and a Czech letter with a diacritic is two of them: *křížovka* is 8 characters
and 11 bytes. The Czech set is 88 characters long and 95 bytes.

There is no `release_notes.txt` yet, on purpose: App Store Connect has no
*What's New* field on an app's first version. From 1.0.1 on, add one per
language describing what changed since the previous version — replace it for
every release rather than appending to it.

The reasoning behind the name, the subtitle and the keywords, what the
competition looks like, what its players complain about, and the alternatives
are in [alternatives.md](alternatives.md).

Checking it. The limits are the easy half — the checks after them are the ones
that catch real mistakes: a word paid for twice across two indexed fields, a
stray space in the keyword list, a paragraph left wrapped at 80 columns, and a
one-line field ending in a newline. The one-line files have none, on purpose: a
copy of the whole file would take it along, and both subtitles are exactly 30
characters.

```bash
python3 - <<'PY'
import os,re
lim={'name.txt':30,'subtitle.txt':30,'keywords.txt':100,
     'promotional_text.txt':170,'description.txt':4000}
bad=0
for loc in ('cs','en-US'):
    d=lambda f:open(os.path.join('AppStore',loc,f),encoding='utf-8').read().rstrip('\n')
    for f,m in lim.items():
        # keywords are limited in UTF-8 bytes - every č, á or ř costs two
        n=len(d(f).encode()) if f=='keywords.txt' else len(d(f)); bad+=n>m
        print(f'{loc:6}{f:22}{n:5}/{m}', 'OK' if n<=m else 'OVER!')
        # a copied newline makes a 30-character subtitle 31
        if f!='description.txt' and open(os.path.join('AppStore',loc,f),encoding='utf-8').read().endswith('\n'):
            bad+=1; print(f'{loc:6}{f}: ends with a newline')
    # a word in two indexed fields is paid for twice and indexed once
    t=lambda f:set(re.findall(r'[\wÀ-ſ]+', d(f).lower()))
    for a,b in (('name.txt','subtitle.txt'),('name.txt','keywords.txt'),
                ('subtitle.txt','keywords.txt')):
        ov=t(a)&t(b); bad+=bool(ov)
        if ov: print(f'{loc:6}DUPLICATED {a} x {b}: {sorted(ov)}')
    # a space after a comma silently costs one of the 100 characters
    if ', ' in d('keywords.txt'): bad+=1; print(f'{loc:6}KEYWORDS: space after comma')
    # App Store Connect keeps newlines - a paragraph has to be a single line
    L=d('description.txt').split('\n')
    for i,l in enumerate(L[:-1]):
        if (l.strip() and L[i+1].strip() and not l.isupper() and not l.startswith(chr(8226))
                and not L[i+1].startswith(chr(8226))
                and not l.rstrip().endswith(('.','!','?',':','…'))):
            bad+=1; print(f'{loc:6}DESCRIPTION line {i+1} wrapped mid-paragraph')
# App Review's Notes field takes 4,000 characters too, and cuts a longer paste short
n=len(open('AppStore/review-notes.txt',encoding='utf-8').read().rstrip('\n')); bad+=n>4000
print(f'{"":6}{"review-notes.txt":22}{n:5}/4000', 'OK' if n<=4000 else 'OVER!')
print('ALL CLEAN' if not bad else f'{bad} problem(s)')
PY
```

Run it from the repository root, not from this directory. Once a
`release_notes.txt` exists, add `'release_notes.txt':4000` to `lim`.

## Which localisations to create, and why two

Keywords never combine across languages — each localisation is its own search
index — but a storefront supports more than one language. Apple's
[App Store localizations](https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations)
table gives every country a default language and, for most, additional
supported ones, and which of them a customer sees depends on their device
language. The usual ASO reading is that a storefront searches the keywords of
every localisation it supports. The rows that matter here (as the Sudoku
project read them on 31 October 2026):

| Storefront | Default language | Additional supported languages | What that means here |
|---|---|---|---|
| United States | English (U.S.) | Arabic, Chinese (Simplified), Chinese (Traditional), French, Korean, Portuguese (Brazil), Russian, Spanish (Mexico), Vietnamese | `en-US` is the listing |
| Czechia | English (U.K.) | **Czech** | `cs` for Czech devices; the rest see the primary language, `en-US` |
| United Kingdom, Ireland | English (U.K.) | — | no English (U.K.) localisation, so the primary language, `en-US` |
| Australia, New Zealand | English (Australia) | English (U.K.) | neither is localised, so the primary language, `en-US` |

So the two folders here are:

- **`en-US`** — primary language of the record, and what every English
  storefront reads.
- **`cs`** — Czechia's additional language, and the one worth the most effort
  per hour. The game is one of very few letter-wheel crosswords built from Czech
  words: the biggest app of the genre in Czechia (Words of Wonders, 50,361 Czech
  ratings) has no Czech words in its listing and a Slovak word in its Czech
  title, and every letter-wheel game that says it uses Czech words has 24
  ratings or fewer (see [alternatives.md](alternatives.md)).

No other language: the game's interface and puzzles are English and Czech only,
and a listing in Spanish or German would send people to puzzles in a language
they did not search in.

## Notes on the individual fields

- **App Name** — has to be globally unique, and it is the single strongest
  ranking signal. It starts with the brand, because that is what the home screen
  says (`INFOPLIST_KEY_CFBundleDisplayName = Wordwander`) and the game's title
  screen too, and Apple wants the two names not to differ in meaning. The rest
  of the 30 characters carries the head term and the strongest modifier:
  `Wordwander: Word Game, No Ads` / `Wordwander: české křížovky`. Nobody else is
  called Wordwander (checked 2 November 2026), but **Word Wanderer** is — a
  letter-wheel game from another developer with 937 US ratings; see *The name*
  in [alternatives.md](alternatives.md).
- **Subtitle** — the second strongest signal and the line people actually read
  in search results. It adds the terms the name could not fit rather than
  repeating it. **No price in it**, in any language, and none in the keywords
  either: guideline 2.3.7 covers every metadata field alike, and *free* /
  *zdarma* is the wording that gets metadata rejected. "No ads" / "bez reklam" is
  not a price and is fine — Apple accepts it in names that have been live for
  years (*Word Puzzle: No Ads, No Wifi!*, *Sudoku ′ No ads*).
- **Keywords** — separate with commas and **no spaces** (a space counts towards
  the limit). Do not repeat words already in the name or subtitle, Apple indexes
  those separately. Do not name a competitor's app or brand — *wordscapes*,
  *zen word*, *word trip*, *words of wonders*, *word cookies* are all somebody
  else's, and grounds for rejection.
- **Description** — write each paragraph as **one long line**. App Store Connect
  keeps newlines exactly as pasted, so a paragraph wrapped at 80 columns in the
  editor comes out ragged on the device while every other paragraph reflows
  around it. On iOS the description is **not indexed for search** — it is a
  conversion field only, so keywords in it buy nothing and the first three lines
  (all most people ever see) are what the effort belongs in.
- **Promotional Text** — the only text on the product page that can be changed
  at any time, without a new version or build. Useful for seasonal or topical
  messages. Like the description, it is not indexed for search.

## Settings that are not filled in with text

**App Information** (shared across all languages):

- Primary Category: **Games**, subcategories **Word** and **Puzzle** — where
  every large game of the genre sits (Wordscapes, Words of Wonders, Word
  Cookies). `INFOPLIST_KEY_LSApplicationCategoryType =
  public.app-category.word-games` is already set on the app target, so the
  bundle says the same thing about itself.
- Secondary Category: **Education**. Every word a player finds goes into the
  Lexicon with its dictionary definition (for Czech words, the translation from
  iOS's Czech–English dictionary: iOS has no Czech one of its own), and the game has full English and
  Czech puzzle sets, so vocabulary is a real part of it; and Education is a far
  smaller room than Entertainment, where most of the competition puts its
  secondary category and where an app without six-figure ratings never shows.
  The Sudoku listing made the same choice. If Apple's reviewer disagrees,
  Entertainment is the conventional fallback; nothing else depends on it.
- Content Rights: **Yes, it contains third-party content, and you have the
  rights to use it.** The word lists are built from ENABLE (public domain) and
  wordfreq (CC BY-SA 4.0, with the SUBTLEX and OpenSubtitles data its terms ask
  to be credited too), all credited in Settings › Acknowledgements; the
  landscapes, the icon, the interface and the sounds are the game's own. Every
  term of those sources is met (see *Word data and licences* in the project
  README): the credits are in the app, the packs are shared under CC BY-SA 4.0
  with their sources and changes in `LICENSE.md`, and the public repository is
  the copy without DRM that wordfreq's licence asks for. The Czech Hunspell
  dictionary (GPL) is only a spelling check while the packs are generated, and
  nothing of it ships. Keep the repository public.
- **Gambling: No.** No real money, no wagering, and every reward is fixed and
  shown in advance — no spins, chests or loot boxes, which many games of this
  genre do have (Wordscapes is 16+ for "Infrequent Simulated Gambling").

**Age Rating: 4+.** Every answer is *None* or *No*:

- In-App Controls: Parental Controls **No**, Age Assurance **No**.
- Capabilities: Unrestricted Web Access, User-Generated Content, Social Media,
  Messaging and Chat — all **No**. **Advertising — No**, which is the answer 36
  of the 41 biggest games of the genre cannot give.
- Mature Themes, Sexuality or Nudity, Violence, Profanity or Crude Humor — all
  **None**. Vulgar words and slurs are not even accepted as bonus words, in any of
  their forms (the generator's block lists and inflection rules, checked by
  `PuzzlePackTests.puzzlesAreFamilyFriendly`); a few
  mildly crude ones (*fart*, *naked*) count as bonus words when a player spells
  them, and never appear in a crossword, nor do insults or grim subjects (death,
  weapons, drugs, spirits, gambling, grave illness). The gravest (*murder*,
  *suicide*, *rape*, *slavery*, *heroin*) are not accepted at all.
- Horror/Fear Themes — **None**: calm landscapes, nothing that startles.
- Alcohol, Tobacco, or Drug Use or References — **None**. The crossword leaves out
  spirits, tobacco and drugs; everyday food words that any dictionary has, such as
  *beer*, *wine*, *pivo* or *víno*, do appear among its answers, which shows or
  encourages nobody's drinking. Nothing in the game depicts or mentions using
  them.
- Medical or Wellness: **No** to both. Do not answer *Health or Wellness Topics*
  with Yes on the strength of "word games are good for your brain" — it moves the
  rating to 9+, and the listing deliberately makes no such claim.
- Chance-Based Activities: Gambling, Simulated Gambling, Contests, Loot Boxes —
  all **None**.

**Pricing and Availability:** Free, in every country and region **except China
mainland** — in *Pricing and Availability → App Availability*, choose *Specific
Countries or Regions* and deselect it. Games there "must secure an approval
number" from China's NPPA (Apple's
[App information](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information)
reference), which this project does not have. Left selected, it does not block
the submission — Connect just reports the app as unavailable there — but
deselecting it says so up front.

The same page offers *iPhone and iPad Apps on Apple Silicon Macs* and *Apple
Vision Pro* only to builds that allow them, and this one doesn't: the target
sets `SUPPORTS_MAC_DESIGNED_FOR_IPHONE_IPAD` and
`SUPPORTS_XR_DESIGNED_FOR_IPHONE_IPAD` to `NO`, matching the listing's "On
iPhone and iPad". Neither has been tried: the game has only been played on
iPhone and iPad simulators (this Mac has no visionOS runtime, and running it as
*Designed for iPad* on the Mac needs the Mac registered with the developer
account). Once it has been played through on either, turning the setting back
on takes a new build.

**App Privacy:** click *Get Started* → **"No, we do not collect data from this
app"**. The app has no networking code, no third-party SDKs, and stores
everything on the device in one JSON file in Application Support
(`PlayerStore`), which needs no required-reason declaration;
`crosswords/PrivacyInfo.xcprivacy` declares no tracking, no collected data and
no required-reason APIs (UserDefaults is read only by the `#if DEBUG` launch
arguments, which are not in a release build). The optional daily reminder is a
local notification. A **privacy policy URL is still mandatory** — the text is
ready in [privacy-policy/](privacy-policy/); the simplest home is the
repository itself, which is public:
`https://github.com/RobertLib/crosswords/blob/main/AppStore/privacy-policy/en.md`
(push first). GitHub Pages or your own site work just as well.

**Accessibility Nutrition Labels** (App Store Connect → the app → *App
Accessibility*): voluntary, shown on the product page from iOS 26 on. Declare
only what has been checked, for iPhone and iPad:

- **VoiceOver: Yes.** Every wheel letter is a button, Submit word and Clear
  appear, the crossword reads out how many words are found and the pattern of
  each missing one, and Spotlight's squares can be chosen — a whole level can be
  played by ear. Check it on a device before declaring.
- **Reduced Motion: Yes.** The landscapes stand still; the confetti, the
  floating title, the shake of a wrong word and the looping hand of the swipe
  tutorial are left out; revealed letters, toasts, the next level and the
  level-complete card fade in rather than spring, slide or zoom; found words fade
  instead of flying off, and shuffled letters move without gliding.
- **Dark Interface: No.** The menus follow the system appearance, but the game
  screen is its landscape, and half of the landscapes are daylight.
- **Larger Text: No.** The menus grow with Dynamic Type, and their rows stack at
  the accessibility sizes rather than squeezing their labels; the game screen is
  scaled geometry and does not.
- **Sufficient Contrast:** white text on the coloured fills meets WCAG (4.5:1 for
  small text, 3:1 for large — `ThemeTests` checks every landscape's accent), and
  white text straight on a landscape has a dark rim. Answer it once checked on a
  device with Increase Contrast on.
- **Voice Control:** with Settings → *Spell by tapping* on, every letter is a
  labelled button ("Tap S"), and *Submit word* and *Clear* appear, so a level
  needs no swipe. Declare it once a level has been played that way on a device.
- **Differentiate Without Color Alone:** leave unanswered until checked.
- **Captions, Audio Descriptions:** not applicable — no video or spoken content.

**Support URL:** a mandatory field. The repository page
(`https://github.com/RobertLib/crosswords`) or a simple page with an e-mail
address will do.

**Marketing URL:** optional, feel free to leave it empty.

**Encryption:** `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO` is already set
in the project, so the export compliance question never appears when the build is
uploaded.

**App Review Information** → the note for the reviewer is in
[review-notes.txt](review-notes.txt). It explains the coins up front — a
reviewer who sees prices on the hint buttons and no store will otherwise ask
where they are bought. The game needs neither an account nor a demo login —
leave *Sign-in required* switched off.

**In-App Events** (App Store Connect → the app → *Events*): not needed to ship,
but the largest piece of indexed text left once the listing is live: the event
**name (30)** and **short description (50)** are indexed for search in every
localisation. The game has a natural event to hang them on — a monthly
*Challenge* around the daily puzzle ("Daily Crossword Streak" / "Denní křížovka
celý měsíc": solve every daily puzzle of the month, which the calendar, the
streak and the *Daily Ritual* and *Steady Flame* achievements already count). A
new one each month keeps a fresh indexed name live all year. Worth setting up
after launch.

## Release procedure

1. Xcode → Signing & Capabilities, check the team `K6GM85X5D7` and the bundle ID
   `cz.rob.crosswords`.
2. App Store Connect → **Apps → +** → new record, bundle ID `cz.rob.crosswords`,
   primary language **English (U.S.)** — the fallback for every storefront
   without its own localisation — SKU e.g. `wordwander-001`, name from
   `en-US/name.txt`. Names are globally unique; if it has been taken by the time
   you get there, see the alternatives in [alternatives.md](alternatives.md).
3. Add the other localisation: App Information → the language switch, top right
   → **Czech**.
4. Fill in the texts from this directory in every language.
5. Build the media with `Tools/AppStoreMedia/media.sh` and then
   `Tools/AppStoreMedia/compose.sh`, and upload the **composed** screenshots and
   the previews — see [screenshots.md](screenshots.md). Every slot has a folder
   and a preview file of its own: **iPhone 6.1"/6.3"** (`iphone-6.3`), the one
   iPhone slot Connect requires; **iPhone 6.9"** (`iphone-6.9`); **iPad 13"**
   (`ipad-13`), required too, because the app is universal; and **iPhone Duo**
   (`iphone-duo`), required from April 2027 — its screenshots need one manual
   step, see screenshots.md.
   Apple's screenshot specification contradicts itself on the larger iPhones: its
   list of required sizes names only the 6.3" slot, but the cell for the 6.5"
   slot still says it is required when no 6.9" screenshots are provided. So the
   6.9" slot is filled as well (*iPhone 18 Pro Max*, 1320 × 2868), and whichever
   reading Connect applies, nothing is missing. The 886 × 1920 preview serves
   every iPhone slot.
6. Check `MARKETING_VERSION` (1.0) and **`CURRENT_PROJECT_VERSION`** (the build
   number, `CFBundleVersion`, now 1) in the project. Raise the build number on
   every upload, rejected ones included.
7. Xcode → Product → Archive → Distribute App → App Store Connect → Upload.
8. Wait for the build to process (10–60 min), then select it in the *Build*
   section.
9. Fill in App Privacy, Age Rating, Pricing and Availability (China mainland
   deselected, see above) and the Accessibility Nutrition Labels.
10. App Information → **License Agreement**: Apple's standard agreement with the
    clause that keeps the puzzle packs under CC BY-SA 4.0, see
    [licence-agreement.md](licence-agreement.md).
11. **Add for Review** → *Submit*.

From 1.0.1 on it is **+ Version or Platform** instead of a new record; the
localisations are inherited, `release_notes.txt` is the one field that has to
change for every version, and the rest only needs touching when it is actually
out of date. Of the listing's texts and media, only Promotional Text changes at
any time. Screenshots and previews belong to a version, so new media go up with
the next version — or, on the live app, through
[Product Page Optimization](https://developer.apple.com/help/app-store-connect/create-product-page-optimization-tests/apply-a-test-treatment-to-your-product-page):
test the new set as a treatment, then apply it to the original product page.
The first test worth running is the order of the first three screenshots.
